# Working conventions for Claude in this repository

This file is read at the start of every session. It says how work is recorded, so that
knowledge survives between sessions and between Joon and Claude. The documents it refers to
live under `docs/`; `docs/index.md` lists them all.

Joon's personal rules are in his global `CLAUDE.md`, and the conventions they rest on —
design, naming, typing, the JAX ecosystem — are in the `code-conventions` skill.
[`docs/coding-standards.md`](docs/coding-standards.md) says where each convention is
enforced here, and which checks stand in for prose.

## Start of a session

1. Read `docs/index.md`, then `docs/architecture.md` (what the code is now), then the
   current phase in `docs/roadmap.md` (what is being done and why).
2. Find the branch's change document `docs/changes/<YYYY-MM-DD>-<branch>.md`. Its
   **Review notes** table is the current state of the review: rows with *Thoughts* or
   *Modifications* filled in by Joon are instructions for this session. Read them before
   touching code.
3. Check `docs/findings.md` for anything that constrains the task.

## Change documents

Every branch has a companion document `docs/changes/<YYYY-MM-DD>-<branch>.md`, committed
with the code. It is the reviewer's map of the change, not a changelog, and it is also the
*plan* for the branch: it is written before the work (`status: planned`), updated as the
work lands (`in-progress`, `landed`), and closed at merge (`merged`). Sections:

- **Summary** — what the branch does and why, in a few sentences; which roadmap items.
- **Files** — every file touched, one line each. Must match `git diff --stat main...HEAD`
  (names); `scripts/check_docs.py` checks this. Planned files are marked *(planned)*.
- **Design** — decisions not obvious from the code, each with the rejected alternative and
  why; link to an ADR in `docs/decisions/` when the decision is structural.
- **Bugs fixed** — pre-existing bugs found on the way, with the symptom.
- **Findings** — anything that bears on *reported results* or on later phases; also
  appended to `docs/findings.md`.
- **Tests** — what the new tests pin down and how to run them (tier, markers, env vars).
- **Open issues** — things deliberately left alone, with the reason.
- **Review notes** — a table *Change* | *Thoughts* | *Modifications*. Claude pre-populates
  one row per file touched (*Change* = file + one-line summary) and leaves the other two
  columns blank. Joon fills them in while vetting. Claude never edits *Thoughts* or
  *Modifications* except when asked to, and treats them as the current state of the review.
  A *Modifications* entry that changes code is committed with the touched test files green
  (`uv run pytest <files> -m "not regression and not slow"`), like any other edit.

Claude updates the change document in the same commit as any code change on the branch.

## End of a session (or of any commit that changes structure)

- Change document updated (Files, Design, Tests, Review-notes rows for new files).
- `docs/roadmap.md`: finished items moved to the **Done** ledger (append at the end,
  never insert, never delete); phase tables kept *correct now*.
- `docs/architecture.md` updated if a module moved, was renamed, added or removed.
- `docs/findings.md` appended if anything concerns a reported result.
- `docs/verification.md` updated if a numerics claim gained or lost a test.
- `uv run python scripts/check_docs.py` passes.

## Repository facts

- Python ≥ 3.13 (`.python-version`; `copy.replace` is the copy-with-changes), `uv sync` (add `--extra cuda` on GPU machines); tests with `uv run pytest`.
  Tiers, tolerances, goldens policy and the checks are in `docs/coding-standards.md`.
- Read the baseline before editing — the branch change document's *Tests* and *Open
  issues* — rather than running a full tier to discover what is already red.
- Pre-commit: ruff check `--fix`, ruff format, nbstripout.
- Notebook outputs are stripped by a git filter (`nbstripout --install` once per clone).
  Paper figures are regenerated by scripts, not kept as outputs.
- `third_party/icon` is a git submodule (`git submodule update --init`); not imported by
  `src`.
- `import juliacall` or `import juliapkg` *installs Julia* (1 GB) on a machine without it;
  probe for the Julia side with `simulations.backends.trixi.available()`, never by importing.
  Set-up is `uv run python scripts/setup_julia.py`; `uv sync` here takes `--group dev
  --extra cuda`.
- `git log -p docs/roadmap.md` is the project diary; `git blame` dates every Done row.
- Tags cannot be pushed from Claude's sessions (proxy policy); Joon pushes tags.
- Numerics conventions (stencil `(a, b)`, faces, padding, BCs, axis handling) are in
  `docs/design/fv-conventions.md` and are not restated in code comments.
- Markdown must render on GitHub: display math only as a standalone `$$` block, never
  `$$…$$` inside a paragraph. Every document under `docs/` starts with a frontmatter block
  (`type`, `status`, `updated`, plus `verified_by` / `sources` / `id` where relevant);
  `status` ∈ {`current`, `planned`, `in-progress`, `landed`, `merged`, `agreed`,
  `accepted`, `amended`, `tentative`, `historical`}.
- Provenance labels in design documents: **[cited]** = from a named source, **[code]** =
  verified in the tree, **[deduced]** = Claude's inference. Keep them.
